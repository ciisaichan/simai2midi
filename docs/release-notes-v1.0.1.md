# simai2midi v1.0.1

**修复：滑星的「经过键」不再默认展开成拍手点** —— 消除了一类听感上的不规律双击。

完整对比：https://github.com/ciisaichan/simai2midi/compare/v1.0.0...v1.0.1

## 修的是什么

v1.0.0 默认会把滑星的**经过键**也算成拍手点：

- V 型滑星（如 `2V48`）的 via 键
- 连结滑星（如 `3-5-2-8`）的中间段终点

这些经过键的时刻是按**路径长度比例**算出的几何值，不在音乐网格上；它们常常只比
邻近的 TAP 早或晚 **8–32ms**，挨在一起听就是一次**双击 / 打嗝**。而游戏里一条滑星
只计 **1 个 note**（官方物量口径），所以这类经过键在「正解音」里并不存在。

实测例子（*モエチャッカファイア* Master，BPM 163）：

| 时刻 | 来源 | 与下一击的间隔 |
| --- | --- | --- |
| 130.842s | `3-5-2-8[8:3]b` 的中间段经过键 | → tap `6` @130.859s，**17.1ms** |
| 131.043s | tap `7` | → `3-5-2-8[8:3]b` 的中间段经过键 @131.060s，**17.1ms** |
| 134.347s | `6V83V15[2:1]` 的 via | → tap `4` @134.356s，**8.4ms** |

## 现在的行为

| | v1.0.0 | v1.0.1 |
| --- | --- | --- |
| 默认（不带参数） | 星头 + 经过键（V 的 via、连结段中间键） | **只有星头** —— 一条 slide = 1 个拍手点 |
| `--slide-dense` | 星头 + 经过键 + 弧线（`> < ^`）沿途按钮 | 不变（= 星头 + 全部经过键，完整滚奏） |
| `--tails` | 追加 HOLD / SLIDE 终点尾判 | 不变 |

v1.0.0 那个中间状态（「只在 V 型与连结段才展开」）**已取消**：它既不是游戏里的
note，时间又是几何值，两头不靠。需要滚奏请显式开 `--slide-dense`。

## 影响范围

- 拍手点数下降，**与音符数相等**（官方物量口径）——对全部 12 份回归样本逐一成立
- 只有单段滑星的普通段落不受影响；受影响的是含 V 型、连结滑星的段落
- **已生成的 MIDI / MusicXML / PDF 建议重新生成**，以获得修正后的结果

## 验证

| 检查 | v1.0.0 | v1.0.1 |
| --- | --- | --- |
| *モエチャッカファイア* 的 8–32ms 双击 | 6 处 | **0 处** |
| 同曲 拍手点 / 音符数 | 853 / 842 | **842 / 842** |
| 12 份样本「拍手点 == 音符数」 | — | **12/12 全部成立** |
| 192 分网格偏离（*モエチャッカファイア*） | 最大 2.6ms | 最大 2.6ms，脱网格 **0** |
| 192 分网格偏离（*PANDORA PARADOXXX* ReMaster，1253 点） | — | 最大 **2.8ms**，脱网格 **0** |
| 单元测试（parser / writer / score_writer） | 0 failure | **0 failure** |

> 排查判据的坑（写在这里免得以后再踩）：**不要**用「相邻两击间隔 ≤35ms」当双击判据
> —— 密集曲的 32/64 分连打会产生大量合法的 25–33ms 相邻点（*PANDORA PARADOXXX*
> ReMaster 就有 101 处，全部合法）。正确判据是 **192 分网格（1/48 拍）偏离**：
> 几何算出的经过键偏 1ms 以上，正常谱面拍点最大只偏不到 1ms（tick 取整）。

## 升级

```bash
git pull
python simai2midi.py maidata.txt -O out/     # 重新生成即可
```

命令行参数与用法**完全兼容**，只有默认输出变了。想恢复 v1.0.0 的密度可用
`--slide-dense`（注意它比旧默认更密：弧线沿途按钮也会展开）。
